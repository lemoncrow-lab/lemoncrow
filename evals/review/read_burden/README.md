# Read-burden corpus

Real, public pull requests written by coding agents and pushed more than once, stored so the read-burden benchmark
(`src/lemoncrow/pro/capabilities/review/evaluation/read_burden.py`) can recompute its counts offline. The report is
[report.md](report.md), regenerated byte-identically by `make review-read-burden-report`. The gate is
`tests/gateway/test_review_read_burden.py`.

**The corpus is not in the public mirror, and is not published.** `prs/` holds about 14 MB (inflated) of verbatim
third-party source, each pull request under its own repository's licence; `scripts/public-paths.txt` denies
`evals/review/read_burden/prs/`. The owner's decision (OWNER-18) is to share the benchmark as the report, the list of
pull requests and revisions, and a script that fetches them from GitHub and checks them against the manifest, with no
third-party code redistributed. `make review-read-burden-bundle` writes that bundle (to `build/read-burden-bundle`, or
`BUNDLE_DIR=`): `report.md`, `manifest.json`, `sources.json`, `expected.json`, the fetcher
(`scripts/fetch_read_burden_corpus.py`, standard library and `git`), a README on how to fetch and recompute, and an
attribution list. It holds no corpus text; publishing it is the owner's step. The collector
`scripts/collect_read_burden_corpus.py` and the gate test are not in the public mirror either. What is public: this
README, `report.md`, `expected.json`, `manifest.json`, `sources.json`, `licences.json.gz` and the benchmark module.

`sources.json` is the fetch list, derived from the stored corpus by `make review-read-burden-report` (never edited by
hand; a test fails when it drifts): for every pull request its record without the file texts, so each revision's
`base_sha` and `head_sha` and every changed file's path, status and git blob id, and for every repository the commit and
blob ids of its licence files. It is a separate file, not part of `manifest.json`, so the stored size the report prints
does not depend on it. A reader of the public mirror fetches the pull requests again and recomputes the report:

```bash
python3 scripts/fetch_read_burden_corpus.py evals/review/read_burden/sources.json fetched/   # all, or --pr 'owner/repo#N'
uv run python -m lemoncrow.pro.capabilities.review.evaluation.read_burden --corpus fetched --report fetched/report.md
```

The fetcher reads each file with `git` over https (no token) and keeps it only if its git blob id equals the manifest's;
a commit GitHub no longer serves is reported by pull request, revision and sha, never substituted. A complete fetch
rebuilds `prs/` and `licences.json.gz` byte for byte (the files are written as the collector writes them), so the report
recomputed from it is byte-identical. To collect afresh instead, from a checkout that has the collector:

```bash
uv run python scripts/collect_read_burden_corpus.py --out evals/review/read_burden   # collect (public, read-only GitHub, needs `gh`)
uv run python scripts/collect_read_burden_corpus.py --out evals/review/read_burden --licences-only   # licence texts only
make review-read-burden-report                                                       # regenerate report.md and sources.json (offline)
make review-read-burden-report WRITE_EXPECTED=1                                      # also record new expected.json
```

A fresh collection finds the pull requests the search returns that day, so its counts differ from the recorded ones.

## What is stored

`prs/<owner>__<repo>_<n>.json.gz` holds one pull request: its repository, licence (SPDX), an attribution line, the agent
and how it was identified, and for every revision the changed files with the base and head text of each. Texts are stored
once, content-addressed by git blob id; the loader recomputes every blob id and rejects a record whose text does not
match, whose licence is not MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause or ISC, that has no attribution, or whose
`identified_by` names no login from the agent table below (or one that does not map to the recorded agent). Each record
is inflated at most 4 MB.

`licences.json.gz` holds, per repository, its LICENSE text and, where it has one, its NOTICE text, read from the
repository at the last commit collected from it. The loader requires an entry for every repository in `prs/`, non-empty
texts whose blob ids match, and a LICENSE text that reads as the SPDX id the record declares (MIT, Apache-2.0,
BSD-2-Clause, BSD-3-Clause or ISC, by their standard phrases). A pull request whose repository had **no** licence file at
the collected commit is removed, even if the repository carries one now: GitHub reports the current licence, and a
licence added later does not show what the code was under when it was written. The manifest counts these as
`no licence file at the collected commit`.

The corpus is capped at 10 MB (`prs/`, `licences.json.gz` and `manifest.json`); the loader refuses a larger one.
`manifest.json` lists every pull request, the collection date and why candidates were rejected. `expected.json` is the
gate's recorded result.

Files that are binary, over 200 KB, or unreadable in any revision are omitted from every revision of that pull request
(`omitted_unreadable_files`); pull requests over 60 changed files or 600 KB of changed text are not collected.

## How a pull request is identified as agent-written

Only by the account that opened it. Later pushes to the branch may have been made by a person; nothing here checks who
pushed a given revision, only who opened the pull request. The collector searches for pull requests authored by a GitHub App account
(`author:app/<slug>`) of a known coding agent and keeps one only when GraphQL reports the author's `__typename` as
`Bot` and its login is in a fixed table: `copilot-swe-agent`/`Copilot` (GitHub Copilot coding agent),
`devin-ai-integration` (Devin), `claude` (Claude Code, claude[bot]), `google-labs-jules` (Jules), `cursor` (Cursor
background agent). A human who picks the same name is not counted. Each record's `agent.identified_by` says which login
and which search found it. Agents whose pull requests are opened under a human account (OpenHands, Codex `codex/`
branches) cannot be verified from the author alone and are not in the corpus.

## Revisions

GitHub does not publish when a branch was pushed, and a pull request's commits are not pushes. A **revision** here is a
head commit that was *observed*: at least one of

- `check_suite`: a check suite ran on that commit (a push starts one),
- `review`: a human, other than the author, submitted a review against that commit,
- `force_push_before` / `force_push_after`: the commit on either side of a recorded force push,
- `final_head`: the head of the pull request when collected.

Each is recorded in the revision's `observed_by`. Commits nobody observed are not revisions, so the corpus
**under-counts** pushes; a pull request needs two distinct observed commits with different diffs to enter. For every
revision the diff is `compare/<base ref at collection>...<head>` (three dots), with that comparison's merge-base as the
revision's base. Pull requests with more than 20 observed revisions or more than 100 commits are rejected.

## Selection

The search asks for `is:merged` pull requests only, so an agent pull request that was closed without merging is not in the
corpus. Search results are ordered by comment count and require more than three comments, so discussed pull requests are
over-represented, and agents with many such pull requests (Cursor, Claude, Jules) dominate. Candidates under any other
licence (GPL, AGPL, none) are rejected; the manifest counts each reason. The corpus is what the search returned, not a
random sample of agent pull requests.

## Reviewing the assumptions

The reviewer is assumed to have read and judged every part of revision *n-1*. That is the most favourable honest reading
for every rule set, but it is an assumption, not a measurement. See the report's Limitations.
